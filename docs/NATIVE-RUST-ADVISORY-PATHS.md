# GoreeCloud PDF Manager — Native Rust advisory path evidence

**Evidence type:** Local Cargo.lock dependency graph only. **Not** a vulnerability-exploitation test, license clearance, cross-platform feature-resolution audit, installed desktop acceptance, or release approval.

The permitted Tauri source uses a Cargo.lock with **664 locked package-version identities**. The two Rust vulnerabilities that remain open in GitHub Dependabot are tracked here without executing dependencies, downloading packages, compiling binaries, reading user files, or altering the lockfile:

| Advisory | Locked version | Shortest observed root-to-package path |
| --- | --- | --- |
| [GHSA-wrw7-89jp-8q8g](https://github.com/advisories/GHSA-wrw7-89jp-8q8g) | `glib 0.18.5` | GoreeCloud PDF Manager → `tauri 2.11.5` → `gtk 0.18.2` → `glib 0.18.5` |
| [GHSA-cq8v-f236-94qc](https://github.com/advisories/GHSA-cq8v-f236-94qc) | `rand 0.7.3` | GoreeCloud PDF Manager → `tauri 2.11.5` → `tauri-utils 2.10.2` → `kuchikiki 0.8.8-speedreader` → `selectors 0.24.0` → `phf_codegen 0.8.0` → `phf_generator 0.8.0` → `rand 0.7.3` |

The evidence is generated by Python-standard-library-only `scripts/native_advisory_paths.py` from **the current source lockfile**. It tracks name-and-version identities, follows exact-version edges and conservatively branches at ambiguous unversioned edges. Any path with an ambiguous version edge is marked as a **candidate**, not an exact resolved route. For these two specific current paths, no ambiguous version edge was used. This still **does not determine Cargo feature flags, target-platform cfg, whether a crate's susceptible function can be reached, or whether the desktop actually ships or executes the code**.

The tool is bounded, detects duplicate package identities, missing dependencies, an invalid root, invalid fields and excessively large graphs, and always marks `runtime_exploitability: NOT_ASSESSED`, `source_license_cleared: false`, `security_release_approved: false` and `remediation_status: NOT_VERIFIED`. If a future resolved lockfile removes either version, a subsequent analysis must still confirm the relevant advisory and dependency migration; the tool never automatically declares vulnerabilities fixed.

## CI and reproduction

The separate read-only job under [Dependency advisory gates](../.github/workflows/dependency-audit.yml) verifies **ten isolated synthetic graph tests**, writes two independent JSON reports from the same committed Cargo.lock, compares them byte-for-byte, validates the conservative status fields, and retains the report as a nonrelease GitHub Actions artifact for seven days. It does not run Cargo or install native packages.

```bash
python3 -m unittest discover -s scripts/tests -p test_native_advisory_paths.py -v
python3 scripts/native_advisory_paths.py --output /tmp/gcpdf-native-lock-1.json
python3 scripts/native_advisory_paths.py --output /tmp/gcpdf-native-lock-2.json
cmp /tmp/gcpdf-native-lock-1.json /tmp/gcpdf-native-lock-2.json
```

## Release blockers unchanged

Both advisories require a **compatible upstream Tauri/GTK/WebKit/PHF upgrade or an independently approved risk decision** followed by source review, Rust ABI/API and native Linux compile, installed application testing, supported Windows/macOS acceptance and legal/license review. Forcing the vulnerable `glib` or `rand` version independently to a new major number is not a safe compatibility fix. GoreeShield privacy retention, Wardveil untrusted PDF/resource controls, GoreeCloud Identity/UI/Mesh integration, 389 unverified source asset rights and 250 unverified Java runtime library rights remain separate release gates. No installer, code signing or deployment has occurred.
